# `glossary.yaml`

Schema: `schemas/glossary.schema.json`. [All files](index.md).

## The file

`glossary.yaml`: the abbreviations and terms the pack uses, for the Glossary page, Find and Practice, and the terms a step can name.

| Field | Takes | Required | Default | What it is |
| --- | --- | --- | --- | --- |
| `terms` | list of [GlossaryEntry](#glossaryentry) | yes |  | Every term, in any order: the Glossary sorts them A to Z. |

## GlossaryEntry

One term and its meaning.

| Field | Takes | Required | Default | What it is |
| --- | --- | --- | --- | --- |
| `meaning` | text | yes |  | What it means. When the term is in capitals and the first sentence is a short name for it, the Glossary shows that sentence as its expansion and the rest as its meaning, unless `labels.yaml` lists the term in `glossary_exceptions`. |
| `step_term` | true or false |  |  | `false` for a unit or a plain abbreviation (LB, FT, ENG): it stays in the glossary but is never one of a step's terms, which name what a learner needs (panels and systems). |
| `term` | text | yes |  | The term as steps and panels write it, e.g. `APU`. Each term is listed once; a step's `terms` name it. |
