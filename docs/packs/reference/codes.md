# Problem codes

Every problem `involo-pack check` (and the app, when it installs a pack) can report has a stable code.
A code never changes meaning and is never reused. `involo-pack explain <code>` prints the same entry.
There are 126 codes. [All files](index.md).

## P00xx: Reading the files and building the pack

### P0001: A file can't be read

A file the pack needs could not be opened: it is missing, or the folder can't be read. The manifest names every data file by its path in the pack folder.

How to fix it: Check that the file exists at the path pack.json gives, spelled the same way, and that you can read it.

### P0002: A data file doesn't read

A YAML file is not valid YAML, or it does not match its file's format: a field the format doesn't have, a missing required field, or a value of the wrong type. The message gives the line and column where reading stopped.

How to fix it: Fix the file at the line given. `involo-pack describe <file>` lists the fields the file takes.

### P0003: pack.json doesn't read

pack.json is not valid JSON, or it does not match the manifest's format. The message gives the line and column where reading stopped.

How to fix it: Fix pack.json at the line given. `involo-pack describe pack.json` lists its fields.

### P0004: A pack format this version doesn't read

pack.json's `schemaVersion` names a pack format older than the oldest this version reads, or newer than the newest.

How to fix it: Set `schemaVersion` to the format this version of involo-pack reads, and move the pack to it.

### P0005: A file the pack can't use

A file is too large, is not UTF-8 text, or is named by a path that leaves the pack folder.

How to fix it: Keep every data file inside the pack folder, as UTF-8 text, under the size limit; split a large file in two.

### P0006: The parent pack isn't found

The pack `extends` another pack, which is looked for beside it and in the folders `--parents` names. None of them holds a pack with that id.

How to fix it: Put the parent's folder beside this one, or pass its folder with `--parents <dir>`.

### P0007: The pack can't be built over its parent

The pack can't be built from its `extends` and `patches`: the `extends` chain makes a cycle or is too long, the parent found is of another version or format, pack.json holds fields only `involo-pack build` writes, or a patch names no target or more than one, matches nothing, or changes a field in a way its target doesn't allow. The message says which.

How to fix it: Fix what the message names: the `extends` entry, pack.json, or the patch it quotes.

### P0008: Over a size limit

The pack is over one of the limits every pack keeps to: too many steps or glossary terms, or a name that is too long. A pack over a limit is refused for that alone, before the other checks run.

How to fix it: Shorten the name, or split the pack's content so it keeps within the limit the message gives.

## P01xx: pack.json and the files in the folder

### P0101: The pack id isn't valid

A pack id is written in lower-case letters, digits, dots and dashes. Step ids start with it, and the catalog names the pack's file after it.

How to fix it: Change `id` in pack.json to lower-case letters, digits, dots and dashes, such as `my-twin`.

### P0102: An aircraft pack with no lists

An aircraft pack must list at least one checklist file in pack.json's `checklists`.

How to fix it: Add a list file and name it in `checklists`.

### P0103: An aircraft pack with no phases file

An aircraft pack places its lists in phases, so pack.json must name a phases file.

How to fix it: Add `"phases": "phases.yaml"` to pack.json, and write the file.

### P0104: A basis tag isn't valid

Basis tags name the kind of material a list was checked against. Each is written in lower-case letters, digits and dashes.

How to fix it: Write the tag in lower-case letters, digits and dashes, such as `vendor-docs`.

### P0105: An aircraft pack with no aircraft

An aircraft pack says which aircraft it is for in pack.json's `aircraft` block: family, name, icaoTypes, simulator and developer.

How to fix it: Add the `aircraft` block to pack.json.

### P0106: A library pack with an aircraft

A library pack is only ever a parent; the packs that extend it name their own aircraft.

How to fix it: Remove the `aircraft` block, or make the pack `"kind": "aircraft"`.

### P0107: No ICAO type designator

`aircraft.icaoTypes` lists the ICAO type designators the pack is for, at least one. The app warns when a flight plan is for another type.

How to fix it: Add the aircraft's type designator to `aircraft.icaoTypes`.

### P0108: Not an ICAO type designator

An ICAO type designator is two to four capital letters and digits, starting with a letter.

How to fix it: Write the designator in capitals, such as `B738` or `A20N`.

### P0109: An empty aircraft field

Every field of pack.json's `aircraft` block has a value; the app shows them on the Packs page.

How to fix it: Fill in the field the message names.

### P0110: More than one parent

A pack builds on at most one parent, named in `extends`.

How to fix it: Keep one entry in `extends`.

### P0111: The parent's id isn't valid

`extends` names its parent by pack id, which is lower-case letters, digits, dots and dashes.

How to fix it: Write the parent's id as its pack.json gives it.

### P0112: A pack that extends itself

`extends` names the pack's own id.

How to fix it: Name the parent pack's id in `extends`, or remove it.

### P0113: A file name Windows reserves

Windows reserves device names such as CON, PRN, AUX, NUL, COM1 and LPT1, even with an extension, so a file named that way can't be checked out there.

How to fix it: Rename the file.

### P0114: An image or PDF in the pack

Packs never carry images, screenshots, PDFs or other files from an aircraft developer, manufacturer or simulator. Panels are drawn from the pack's data.

How to fix it: Remove the file from the pack folder.

## P02xx: Ids and references between files

### P0201: An id used twice

Ids are how files refer to each other, so each one is used once where it must be unique: in the pack, or in its section for a panel item.

How to fix it: Give one of the two a different id, and update whatever refers to it.

### P0202: A step that doesn't exist

Something refers to a step id that no list in the pack has.

How to fix it: Check the spelling against the step's `id`, or add the step.

### P0203: A phase that doesn't exist

Something refers to a phase id that phases.yaml doesn't define.

How to fix it: Check the spelling against the phase's `id` in phases.yaml, or add the phase.

### P0204: A flight field the pack doesn't define

A step or CDU text names a flight field that flight.yaml doesn't define.

How to fix it: Check the spelling against flight.yaml's field ids, or add the field there.

### P0205: A control that doesn't exist

Something refers to a control id that controls.yaml doesn't define.

How to fix it: Check the spelling against controls.yaml, or add the control there.

### P0206: An option that doesn't exist

Something names a user option (in `decide`, `when`, `expect_when`, `show_if`, `suggested_by` or an alias) that phases.yaml's `options` doesn't define.

How to fix it: Check the spelling against the option ids in phases.yaml, or add the option.

### P0207: A value an option doesn't have

Something names a value of a user option that is not one of the option's `values`.

How to fix it: Use one of the option's `values`, or add the value to the option.

### P0208: A test with nothing in it

A `show_if` test lists nothing: `one_of` needs at least one value, and `all_of` or `any_of` at least one test.

How to fix it: Add what the test checks, or remove the test.

### P0209: A zone that doesn't exist

A control or an overview area names a flight deck zone that controls.yaml doesn't define.

How to fix it: Check the spelling against the zones in controls.yaml, or add the zone.

### P0210: A list that doesn't exist

A phase or a message names a list id that no list file in the pack has.

How to fix it: Check the spelling against the list's `id`, or add the list and name its file in pack.json.

### P0211: A walkthrough that doesn't exist

A step's `opens` names a CDU walkthrough that cdu.yaml doesn't define.

How to fix it: Check the spelling against the walkthrough ids in cdu.yaml.

### P0212: A how note that doesn't exist

A step's `how` names a note that notes.yaml doesn't define.

How to fix it: Check the spelling against the note ids in notes.yaml.

### P0213: An explanation that doesn't exist

A step's `explain` names an explanation that notes.yaml doesn't define.

How to fix it: Check the spelling against the explanation ids in notes.yaml.

### P0214: A role the labels don't list

A step's `role` or `respond` names a crew role that labels.yaml's `roles` doesn't list.

How to fix it: Use one of the roles in labels.yaml, or add the role there.

### P0215: An alias to something that doesn't exist

An alias in aliases.yaml points at a step, briefing item, option value or field the pack doesn't have.

How to fix it: Point the alias at an id the pack has, or remove it.

### P0216: An id isn't written as the format asks

Ids are lower-case letters, digits and dashes (flight field ids use underscores instead of dashes and start with a letter), so they read the same in every file and address.

How to fix it: Rewrite the id as the message says, and update whatever refers to it.

## P03xx: Lists and steps

### P0301: `respond` outside a challenge and response list

`respond` names the role that answers a challenge, so it belongs only in a list with `method: challenge_response`.

How to fix it: Remove `respond`, or set the list's `method` to `challenge_response`.

### P0302: A step id of the wrong shape

A step id is `<prefix>.<phase>.<short-name>`, where the prefix is the pack's id or the id of a pack it is built from.

How to fix it: Rename the step to `<pack id>.<phase>.<short name>`, such as `my-twin.before-start.battery`.

### P0303: A step with no text or response

Every step has the text the pilot reads and its expected response.

How to fix it: Fill in the step's `text` and `expect`.

### P0304: `simulator_model` with no note

`simulator_model` marks the step's `note` as true of the simulator model only, so it needs a note to apply to.

How to fix it: Add the `note`, or remove `simulator_model`.

### P0305: `fill` doesn't match the blanks

A step's `fill` gives one entry for each blank (`___`) in its `expect`, in order.

How to fix it: Give `fill` as many entries as `expect` has blanks.

### P0306: `manual` outside a step's `fill`

`manual` marks a blank the pilot fills in by hand, which only a step's `fill` has.

How to fix it: Remove `manual` here.

### P0307: `route_leg` outside CDU text

`route_leg` reads one leg of the route, which only CDU text uses, with an `index` and a `part`.

How to fix it: Use another field in the step, or move the entry to cdu.yaml.

### P0308: A list with no steps

Every list has at least one step.

How to fix it: Add the list's steps, or remove the list and its entry in pack.json.

### P0309: A list with no basis

Every list has a `basis`: the kinds of material it was checked against, by the tags pack.json declares. No per-step citations are kept.

How to fix it: Add `basis: [<tag>]` to the list, with a tag from pack.json's `basisTags`.

### P0310: The list repeats the training notice

The app shows the training notice itself; a copy in a list's `why` reads as part of it.

How to fix it: Remove the notice from the list's `why`.

### P0311: A basis tag pack.json doesn't declare

A list's `basis`, or a label in labels.yaml, names a basis tag that pack.json's `basisTags` doesn't list.

How to fix it: Add the tag to `basisTags` in pack.json, or use one it lists.

### P0312: A list that starts with a branch

A step with `branch: true` opens a branch from the step before it, so a list's first step can't be one.

How to fix it: Remove `branch: true` from the first step, or put a step before it.

### P0313: The note repeats the how steps

A step's note says again what its "How to do it" steps already say.

How to fix it: Keep it in one place: remove it from the note.

### P0314: A list in more than one phase

Each list is placed in exactly one phase in phases.yaml.

How to fix it: Remove the list from all but one phase.

### P0315: A list in no phase

Each list is placed in exactly one phase in phases.yaml, or the app has nowhere to show it.

How to fix it: Add the list's id to a phase's `lists` in phases.yaml.

### P0316: Essentials on a turnaround with no turnaround

A step is marked for Essentials on a turnaround, but phases.yaml declares no `turnaround`.

How to fix it: Declare the `turnaround` in phases.yaml, or remove the marking from the step.

## P04xx: Step targets and glossary terms

### P0401: A term the glossary doesn't have

A step's `terms` names a term that glossary.yaml doesn't define.

How to fix it: Add the term to glossary.yaml, or remove it from the step's `terms`.

### P0402: A term marked as a plain abbreviation

A step's `terms` names a glossary term marked `step_term: false`: a unit or plain abbreviation, which steps don't list.

How to fix it: Remove the term from the step's `terms`.

### P0403: Two targets for one answer

An item has two targets for the same option value, so the step can't say which position is right.

How to fix it: Keep one target for each answer.

### P0404: Targets that depend on several options

An item's targets can depend on one option only.

How to fix it: Make the item's `when` tests all name the same option.

### P0405: No target for before the answer

An item's targets depend on an option, so it needs an `open` target for while the option is not answered yet.

How to fix it: Add a target for the item with `open: true` and no `when`.

### P0406: `expect_when` with the wrong number of blanks

Each `expect_when` value replaces the step's `expect`, so it has as many blanks (`___`) as `expect` does.

How to fix it: Give the value the same number of blanks as the step's `expect`.

### P0407: An answer in `expect_when` twice

`expect_when` gives each option value at most once.

How to fix it: Remove one of the two entries.

### P0408: `expect_when` with no target that depends on it

`expect_when` gives the step's value for an answer, but none of the step's targets depend on that answer.

How to fix it: Add the target for that answer, or remove the `expect_when` entry.

### P0409: A target and the step's wording disagree

A step's targets and its wording say different things: a position set but not said, said but not set, or a light expected on where the wording says out (or the other way).

How to fix it: Make the target and the step's `expect` (or the answer's value) say the same position.

### P0410: A drawn step with no targets

The step's controls are drawn on a panel, so it gives a target for each item it sets or reads.

How to fix it: Add `targets`. `involo-pack suggest-targets <pack>` drafts them from the wording.

### P0411: A target listed twice

A step lists the same target twice.

How to fix it: Remove one of the two.

### P0412: A panel item that doesn't exist

A target or light locator (`panel/section/LABEL/n`) matches no item on the pack's panels.

How to fix it: Check each part of the locator against the panel file: the panel id, the section id, the item's label and which one it is.

### P0413: A target on another control

A step's target is an item that belongs to none of the step's `controls`.

How to fix it: Add the item's control to the step's `controls`, or target an item of the step's controls.

### P0414: A target both open and set

An `open` target leaves the position to the pilot, so it can't also `set` one.

How to fix it: Remove `open` or `set`.

### P0415: The wrong kind of target for the item

A light takes `light` (on or out), not `set`; only a light or legend pushbutton takes `light`.

How to fix it: Use `light` for a light, and `set` with one of its positions for any other item.

### P0416: A position the item doesn't have

A target, rest, legend or `lit_at` names a position that is not one of the item's `positions`.

How to fix it: Use one of the item's positions as its panel file spells it, or add the position.

## P05xx: phases.yaml

### P0501: A Start page entry listed twice

`start_page` lists each option, and `panel_state`, at most once.

How to fix it: Remove the second entry.

### P0502: A Start page entry that isn't asked there

`start_page` lists options asked on the Start page (their `ask_in` names `start`) and `panel_state`.

How to fix it: Add `start` to the option's `ask_in`, or remove the entry.

### P0503: More than one engine start phase

At most one phase has `engine_start`: the one that starts the engines.

How to fix it: Keep `engine_start` on one phase.

### P0504: A reference phase that starts the engines

Reference phases hold lists for any time, so none of them is the one that starts the engines.

How to fix it: Move `engine_start` to a phase of the flight.

### P0505: A Start page option with no style

An option asked on the Start page needs `start` with a `style`: cards or row (or toggle, for two values).

How to fix it: Add `start: { style: cards }` (or `row`) to the option.

### P0506: `start` on an option not asked there

`start` says how the Start page shows an option, so it is only for an option whose `ask_in` names `start`.

How to fix it: Add `start` to `ask_in`, or remove the option's `start`.

### P0507: A toggle of the wrong shape

`style: toggle` is for an option of two values, with `on` naming the value it sets when on; `on` is only for a toggle.

How to fix it: Give the toggle two values and an `on`, or use another style without `on`.

### P0508: `suggests` reads a field that isn't a weight

An option's `suggests` reads a weight field: a number whose unit is LB or KG.

How to fix it: Point `suggests` at a weight field.

### P0509: `ask_in` names a page that doesn't exist

An option's `ask_in` names where the app asks it: `start`, or one of the app's Flight pages.

How to fix it: Use `start` or a Flight page's id.

### P0510: A reference phase's group

Each reference phase has a `group`, one of the groups labels.yaml lists; a phase of the flight has none.

How to fix it: Give the reference phase one of the listed groups, or remove `group` from a flight phase.

### P0511: An option's choices don't match its values

An option's `choices` give one entry for each of its `values`, no more and no fewer.

How to fix it: Give each value exactly one choice.

## P06xx: labels.yaml

### P0601: A role in a seat that doesn't exist

A role in labels.yaml sits in a seat that labels.yaml's `seats` doesn't list.

How to fix it: Use one of the listed seats, or add the seat.

### P0602: A glossary exception that isn't a term

labels.yaml lists a glossary exception that glossary.yaml doesn't define.

How to fix it: Remove the exception, or add the term to glossary.yaml.

## P07xx: flight.yaml

### P0701: A Flight page that doesn't exist

A Flight page, an overview row or a field's place names a page that is not one of the app's Flight pages or the pages `pages` lists, or a group that page doesn't have.

How to fix it: Use a page id from `pages` (or the app's Flight pages), and a group title of that page.

### P0702: A placeholder that names no field

A `{name}` placeholder in an overview row names no flight field.

How to fix it: Use a field id from flight.yaml inside the braces.

### P0703: A placeholder of an unknown form

A placeholder is `{field}` or `{field:grouped}`; no other form exists.

How to fix it: Write `{field}` or `{field:grouped}`.

### P0704: A field of the wrong kind

`with`, `toggle`, `unit` and `units` each name a field of a certain kind: another number or text field, a choice field of two choices, or a choice field.

How to fix it: Point it at a field of the kind the message says.

### P0705: A field that isn't on the page or group

A page's `selected`, or a group's field list, names a field that is not placed there.

How to fix it: Place the field on that page and group, or name one that is.

### P0706: A field id the app uses itself

The app has fields of its own; a pack's flight field can't take one of their ids.

How to fix it: Give the field another id.

### P0707: A choice field's choices

A choice field lists its `choices`; a number or text field has none.

How to fix it: Add `choices` to the choice field, or remove them from the other.

### P0708: A number's settings on another kind of field

Only a number field has a `unit`, `ranges` or `display`.

How to fix it: Remove them, or make the field `kind: number`.

### P0709: A range with min above max

A field's range runs from `min` up to `max`.

How to fix it: Swap the two, or fix the one that is wrong.

### P0710: A range for a unit the field doesn't offer

A range's `unit` is one of the choices of the field the number's `unit` names.

How to fix it: Use one of the unit field's choices, or add it there.

### P0711: A `display` without a scale or step

`display` divides a number by `scale` and rounds it to a multiple of `step`, so both are above 0.

How to fix it: Give `display` a `scale` and a `step` above 0.

### P0712: `strip` on a field not in the strip

`strip` is the text a field shows in the strip, so it is only for a field whose `show_in` includes the strip.

How to fix it: Add `strip` to `show_in`, or remove the field's `strip`.

## P08xx: Panels, lights and the flight deck overview

### P0801: An overview region outside the overview

Each overview region has a size and lies inside the overview's box.

How to fix it: Give the region a width and height, and keep it inside the overview.

### P0802: A section name the same as its title

A section's `name` is for a name other than its title.

How to fix it: Remove `name` to use the title.

### P0803: Lights that share a label

When two lights in a section share a label, each needs a different `which` so the app can tell them apart.

How to fix it: Give each light with that label its own `which`.

### P0804: Positions not in capitals

Drawings print an item's positions as the placard does, which is in capitals.

How to fix it: Write the positions in capitals.

### P0805: A light's color

A light has a `color`; no other item has one.

How to fix it: Add `color` to the light, or remove it from the other item.

### P0806: A size on a control drawn at a standard size

Only a display unit or readout has a `width` or `height`; every other control is drawn at its standard size.

How to fix it: Remove `width` and `height` from the item.

### P0807: A guard on an item that can't have one

Only a toggle switch or push button can be `guarded`.

How to fix it: Remove `guarded`.

### P0808: A selector position with no name

Each of a selector's positions has a name.

How to fix it: Name the position, or remove it.

### P0809: A selector's angles

Only a selector has `angles`: one for each position, from -180 to 180 degrees, each larger than the last as they sweep clockwise.

How to fix it: Give one angle per position, in clockwise order, within -180 to 180.

### P0810: A rest a panel state contradicts

An item rests at one position, but a panel state counts a step as done that sets it to another.

How to fix it: Make the item's `rest` and the panel state agree.

### P0811: A light's `lit_at`

Only a light has `lit_at`, which names a position of an item that shares its control.

How to fix it: Remove `lit_at`, or name a position of an item on the same control.

### P0812: A caption with no short form

An overview region has a caption on an edge but no short form of it, so the step map falls back to the long one.

How to fix it: Add the `<edge>_short` caption.

### P0813: A seat view for a seat that doesn't exist

The overview has a view for a seat that labels.yaml's `seats` doesn't list, so it is never shown.

How to fix it: Use one of the listed seats, or add the seat.

### P0814: An overview view's drawing

An overview view has a size; its shapes, outlines and labels have their points inside it; each place has a name for each outline; a side view with places has one `eye` point.

How to fix it: Fix the part of the view the message names.

### P0815: A region that doesn't exist

A view's place names an overview region that the overview doesn't have.

How to fix it: Check the spelling against the overview's regions.

## P09xx: Panel item kinds and outlines

### P0901: A field the item's kind doesn't take

Each kind of panel item takes its own fields: a rocker or push/pull knob has two positions, only a legend pushbutton has `legends`, only a keypad has `columns`.

How to fix it: Remove the field, or change the item's `kind`.

### P0902: A legend pushbutton's legends

A legend pushbutton has one or two `legends`, each with its `text`, and names the `positions` it is set to.

How to fix it: Give the button one or two legends with text, and its positions.

### P0903: A keypad's keys

A keypad lists its keys, each with a name and each once, as `positions`, and `columns` is at least 1.

How to fix it: List each key once in `positions`, and set `columns` to 1 or more.

### P0904: An outline or item outside its box

An `outline` has three points or more, all inside its box; a section stays inside its panel's outline, and an item inside its section's.

How to fix it: Move the points or the item inside the box.

## P10xx: CDU text, messages, aliases, confirmations and links

### P1001: A `route_leg` entry

`route_leg` needs an `index` (from 1 to the most legs) and a `part`; no other field takes them.

How to fix it: Give `route_leg` its `index` and `part`, or remove them from the other field.

### P1002: `per_page` below 1

`per_page` is how many rows a CDU page shows, so it is at least 1.

How to fix it: Set `per_page` to 1 or more.

### P1003: A `when_known` test

`when_known` names the field it tests, and it can't test `route_leg`; test `route` instead.

How to fix it: Name a field in `when_known`, using `route` for the route.

### P1004: A message with no text or meaning

An alert message has its `text`, as shown, and what it means (`meaning`).

How to fix it: Fill in `text` and `meaning`.

### P1005: A message given twice

The same message text is given twice at one level.

How to fix it: Remove one of the two.

### P1006: `no_list` on a message with a list

`no_list` says why a message has no list, so a message with a `list` doesn't take it.

How to fix it: Remove `no_list` or `list`.

### P1007: An option alias of the wrong shape

An option alias points at `<option>:<value>`.

How to fix it: Write the alias's target as `<option>:<value>`.

### P1008: A confirmation date that isn't a date

A confirmation's `date` is a real date written YYYY-MM-DD.

How to fix it: Write the date as YYYY-MM-DD, such as 2026-11-08.

### P1009: A confirmation recorded twice

The same confirmation (kind and date) is recorded twice.

How to fix it: Remove one of the two.

### P1010: A link on the blocked list

The pack links a site on the blocked list. Packs never link second-hand study material or the sites the project bans.

How to fix it: Remove the link.

### P1011: A third-party link

Packs carry no URLs to third-party material, only to the few places the project allows.

How to fix it: Remove the link, and say what the pilot needs in your own words.
